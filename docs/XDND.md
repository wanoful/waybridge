# Private Xwayland drop adapter

This adapter is an XDND v3–v5 **source** for COPY drops into X11 targets on the
session's private Xwayland server. It follows the [XDND specification](https://wiki.freedesktop.org/www/Specifications/XDND/).
It does not implement X11-origin drags into Wayland/Windows or MOVE/LINK/DELETE.
The application-data source and read-only file delivery retain ownership of the
payload and file lifetime policy; the adapter sends supplied MIME bytes and
never chooses an application command or modifies the source files.

`x11::State.xdnd` owns an asynchronous handle, created when Xwayland becomes
ready and removed on disconnect. All connection, atom, property and selection
I/O runs on one worker with 500 ms socket-poll deadlines. The compositor exchanges
only a latest desired request and a bounded 64-entry outcome queue. Motion is
coalesced while waiting for XdndStatus. Each drag uses a distinct InputOnly source
XID; source/target/generation checks reject late protocol events. Clipboard and
PRIMARY ownership are not used.

Integration API (in `src/xdnd.rs`):

- `xdnd_begin_data_drop(id,x,y,payload,generation) -> Option<bool>`: `None` is a
  non-X11 window, `Some(false)` means denied/unavailable and must not fall through
  to Wayland delivery, `Some(true)` means enqueued, not accepted yet.
- `xdnd_motion(id,x,y,generation) -> Option<bool>`: update the target/position.
- `xdnd_drop(generation)`, `xdnd_cancel(generation)`, `xdnd_cancel_all()`.
- `xdnd_poll() -> Vec<Outcome>`: generation and target XID with `Accepted(bool)`,
  `Dropped`, `Finished(bool)` or `Error(String)`. `Dropped` means the protocol
  drop was sent; successful delivery waits for `Finished(true)`.

Payload is `Arc<BTreeMap<String,Vec<u8>>>`, the existing Clipboard alias. Callers
pass coordinates normalized by `message_position`; the wrapper adds the current
surface geometry/crop origin and cached X11 root placement. A native HWND's
Windows position is never used as an X11 coordinate. Callers must cancel on
viewer disconnect, read-only transition, abandoned data drops and target loss,
and use generation/target identity when accepting outcomes. The common handler
owns `drop_accepted`, deadlines, native cursor status and text/file completion.

The worker implements XdndAware, verified XdndProxy, TypeList, Enter/Position/
Status/Drop/Leave/Finished, selection TARGETS/TIMESTAMP and 32 KiB INCR chunks.
It derives selection time from a PropertyNotify generated by the X server,
not Windows uptime or compositor-relative time. At most 16 supplied MIME types,
8 MiB supplied bytes and 8 concurrent selection conversions are retained.
Text additionally offers UTF8_STRING/TEXT and Latin-1 STRING where representable.
Protocol handshakes time out after 5 idle seconds; complete drop lifetime is
bounded at 120 seconds. The shared handler must retain file leases until its
existing delivery policy allows release.

This initial adapter checkpoint passes compilation; protocol, Qt and integrated
application acceptance is being added separately. It is not a claim of a complete
XDND bridge or successful QQ acceptance.
