Experimental scRGB HDR subset — partial; physical Windows HDR still unverified:

- Default remains SDR; Linux requires `--hdr experimental-scrgb --codec hevc-nvenc|av1-nvenc`, Windows requires `WAYBRIDGE_HDR=1`. `auto` remains H.264. HDR is never inferred from metadata or a physical display capability flag. The opt-in Wayland color-manager v1 exposes only the predefined Windows-scRGB creator (linear Rec.709, 80 nits/unit); ICC/parametric creators are not advertised and incorrect requests are rejected. Surface color is double-buffered, including synchronized subsurfaces. Output/preferred descriptions remain SDR.

- `tests/hdr_video_smoke.py`: real tagged FP16 compositor→CUDA→HEVC Main10 kind7 and AV1 Main10 kind8, each 15-frame IDR/P chain, actual FFmpeg 10-bit decoded pixels/277 distinct luma codes, PQ/BT.2020/NCL metadata, independent alpha16 PNG raw-half fidelity, two-credit pause/resume with live control ping, repeated 960×640/641×481 cached resize epochs/keys, PNG→HDR resume with fresh epoch/key, wrong-codec fallback ignored, explicit monitor SDR transition to correctly tone-mapped PNG, capabilities without explicit HDR/PQ hello refused, and injected fourth CUDA encode rejection preserving the accurate current PNG followed by a fresh CPU capture without application repaint. Opt-in CUDA GL color input — RTX 5070 Ti:

- The native fixture uses a private device EGL/GLES context on NVIDIA, an actual RGBA8 renderbuffer, CUDA GL registration and FFmpeg CUDA AVFrames. `tests/gpu_native_smoke.c` checks every RGBA pixel of a 641×481 nonuniform premultiplied fixture under both vertical orientations, including exact GPU unpremultiply and alpha 0/128/255. - CUDA device selection uses the current GL context's device query and matches its CUDA ordinal explicitly. Registration uses public GL framebuffer attachment queries, not Smithay private layouts. GL resources stay on the compositor thread; only completed independent CUDA frame storage crosses to the encoder. Sources unregister before RBO resize/deletion/disconnect. Cache identity includes CUDA context/input type plus codec, peer/window and dimensions. CUDA memory contributes to the bounded raw queue.

The current image is preserved as exact straight-color/lossless-alpha PNG, a new CPU capture is requested even if the application stops repainting, and CPU NVENC resumes with an independent new epoch. This is deliberate API fault injection, not a physical GPU/driver fault. A separate build with CUDA headers unavailable passes real H.264/alpha/credit/reference/fallback smoke when CUDA is requested; it logs the reason and retains CPU input.
